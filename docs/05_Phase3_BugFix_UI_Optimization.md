## 一、已确认的 BUG 清单

### 🔴 P0 — 致命/必须修复

| 编号 | 模块 | 文件 | 问题描述 | 根因分析 |
|------|------|------|----------|----------|
| B-001 | 播放器 | `VideoPlayer.tsx:94-96` | **直接播放模式下 `loadedmetadata` 事件监听器未清理**。在 `else` 分支中通过 `addEventListener` 注册了事件，但 cleanup 函数只清理了 HLS 实例，未 `removeEventListener`，导致组件反复挂载时产生重复监听器，引发内存泄漏和状态异常。 | 事件监听器生命周期管理缺陷 |
| B-002 | 播放器 | `PlayerPage.tsx:130` | **离开播放页时 `reportPlaybackStopped` 使用闭包旧值**。在 cleanup 中通过 `usePlayerStore.getState()` 取值虽然正确，但 `PlayMethod` 被硬编码为 `'Transcode'` 而非根据实际 `isDirectPlay` 状态判断，这会误导服务器的转码会话管理，导致转码任务不被正确释放。 | 闭包硬编码值 |
| B-003 | 认证 | `client.ts:62-66` | **401 响应拦截器中 `window.location.href = '/login'` 会导致无限循环**。当 token 过期时，登录页的 `getSystemInfoPublic` 等公共接口如果也返回 401（比如服务器配置了鉴权），拦截器会反复触发跳转。且此处应使用 React Router 的 `navigate` 而非直接操作 `window.location`，否则会丢失整个 React 状态树。 | 全局拦截器与页面路由耦合 |
| B-004 | 播放器 | `PlayerPage.tsx:141` | **`useEffect` 依赖数组遗漏**。播放初始化 effect 的 deps 为 `[id, userId]`，但函数体内引用了 `isMuted` 和 `volume`（第 111-112 行），不过由于这些只在初始上报时使用一次，实际影响较小。更严重的是 `reset` 函数未列入依赖。 | useEffect 依赖不完整 |
| B-005 | WebSocket | `useWebSocket.ts:50` | **`connect` 的 `useCallback` 依赖数组缺少 `handleMessage`**。`connect` 函数内引用了 `handleMessage`，但未被列入 deps，导致 WebSocket 消息处理函数可能使用过时的闭包引用，特别是 `toast` 和 `queryClient` 可能已经更新。 | useCallback 闭包陈旧 |

## 二、BUG 修复流程规范

### 2.1 修复工作流

```
发现问题 → 登记编号 → 影响评估 → 编写修复方案 → 实施修复 → 回归测试 → 构建验证 → 标记完成
```

### 2.2 修复原则（铁律）

1. **最小变更原则**：每次修复只改动与该 BUG 直接相关的代码，绝不顺手重构
2. **回归保护**：修复前先运行 `npm run build` 确认基线状态为绿色，修复后再次验证
3. **逐个修复**：一次只修一个 BUG，修完立即 build 验证，再进入下一个
4. **不动正常代码**：如果某处代码"看起来不优雅"但运行正常，在 BUG 修复阶段不去碰它
5. **修复后批注**：在修复的代码块附近保留简短注释，标注修复了什么问题

### 2.3 修复优先级排序

```
P0（致命） → P1（重要） → P2（轻微）
```

在同一优先级内，按模块归类批量修复以减少上下文切换。

## 三、界面优化美化计划

### 3.1 与 Infuse 的差距分析

经过对 Infuse 8 的界面特征比对，当前 JellyPlayer 存在以下主要差距：

| 维度 | Infuse 标准 | JellyPlayer 现状 | 差距评分 |
|------|-------------|-------------------|----------|
| 海报卡片 | 圆润阴影 + 悬停播放按钮 + 3D 微倾斜 | 仅有基础 hover 放大 | ⭐⭐ |
| 详情页 | 全屏背景渐变 + 元数据卡片化呈现 | 背景模糊过重(8px)、信息排版紧凑 | ⭐⭐⭐ |
| 播放器控制条 | 极简毛玻璃底栏 + 拖动缩略图预览 | 功能齐全但视觉粗糙 | ⭐⭐ |
| 空状态 | 精美插图 + 引导文案 | 无空状态设计 | ⭐ |
| 过渡动画 | 页面间丝滑转场 | Suspense 仅白屏 fallback | ⭐⭐ |
| 移动端 | 专属手势交互 + 紧凑布局 | 仅基础响应式 | ⭐⭐⭐ |
| TV 端 | 方向键焦点导航 + 10英尺布局 | 完全未考虑 | ⭐⭐⭐⭐⭐ |

## 五、风险提示

> ⚠️ **严禁在 BUG 修复阶段进行功能重构**。即便发现了更好的架构方案，也应先记录到本文档的"待重构"备注中，等 BUG 全部清除并确认稳定后再考虑。

> ⚠️ **电视端适配是全新领域**，需要引入焦点管理库（如 `@noriginmedia/norigin-spatial-navigation`），这涉及依赖变更，务必提前评估包体积影响。

> ⚠️ **修改 CSS Variables 或全局样式时需格外谨慎**，因为这些改动会影响所有页面和组件的渲染，必须在所有主题（infuse/ocean/forest/royal/sakura）和模式（dark/light）下验证。
